# 24 - Visualization: Design and Aesthetics

## Core Principles

- **Clear Labels:**  All axes, data series, and chart elements MUST have clear, concise, and descriptive labels.  Avoid abbreviations unless they are universally understood by the target audience.
- **Units:**  Always include units of measurement (e.g., "Damage (HP)", "Time (seconds)", "Win Rate (%)").
- **Color:**
    - **Purposeful Use:** Use color strategically to highlight important information, differentiate categories, or show relationships.  Don't use color just for decoration.
    - **Limited Palette:**  Use a limited color palette (e.g., 5-7 colors max).  Too many colors can be overwhelming and distracting.
    - **Consistency:** Use consistent colors across multiple visualizations to represent the same categories or data series.
    - **Accessibility:**  Choose color schemes that are accessible to people with color vision deficiencies.  Avoid red/green combinations.  Use sufficient contrast between colors.
    - **Greyscale First:** Design visualizations in greyscale first, then add color strategically. This helps ensure that the visualization is effective even without color.
- **Data-Ink Ratio:** Maximize the data-ink ratio.  This means minimizing non-data ink (elements that don't represent data, such as unnecessary gridlines, borders, and decorations).
- **White Space:**  Use white space (negative space) effectively to separate elements and improve readability.  Don't overcrowd the visualization.
- **Font Choice:**  Use a clear, legible font.  Avoid decorative fonts.  Use a consistent font throughout the application.
- **Tooltips:**  Provide tooltips to show detailed information on hover or click.  Tooltips should be concise and informative.
- **Avoid 3D Charts (Generally):**  Avoid 3D charts unless the third dimension adds meaningful information.  3D charts often distort data and make it harder to read.
- **Avoid Chartjunk:** Avoid unnecessary visual embellishments that don't add information (e.g., gradients, shadows, excessive gridlines).
- **Legends:** Use legends when necessary to explain the meaning of different colors or symbols.  Position legends appropriately (e.g., near the chart). If possible, label data series directly instead of using a legend.
- **Sorting:** Sort data in a logical order (e.g., ascending or descending order for bar charts, chronological order for time series).
- **Data Ordering:** If showing parts of a whole, order data segments from largest to smallest (unless there's a more logical order).
