# Task ID: 2
# Title: Finalize Atom Refactoring
# Status: in-progress
# Dependencies: 1
# Priority: high
# Description: Complete the refactoring of all atoms in `src/atoms/` to ensure they adhere to the new pattern outlined in `README.md` and established in Task 1.
# Details:
The refactoring process for each atom in `src/atoms/` will involve the following steps:

1.  **Identify Atom:** Determine the specific atom(s) to refactor from the `src/atoms/` directory.
2.  **Read Files:** Review the atom's source file (`src/atoms/{atomName}.ts`), its corresponding test file (`src/atoms/{atomName}.test.ts` if it exists), and the main atom index file (`src/atoms/index.ts`) for any related type definitions or registrations.
3.  **Compare to Pattern:** Cross-reference the atom's current structure with the checklist provided in `README.md` under the section 'Things to check when refactoring atoms to use the new pattern'. This checklist includes verifying:
    *   A single atom per file, with a default export for the atom instance.
    *   Core logic encapsulated in a named `{atomName}Fn` export.
    *   The `{atomName}Fn` is pure, testable, accepts essential parameters, and is correctly utilized by the default exported atom.
    *   The atom's value type is defined and exported from `src/atoms/index.ts` and correctly used within `{atomName}.ts`.
    *   Comprehensive unit tests for `{atomName}Fn` are present in `{atomName}.test.ts`.
    *   The atom is correctly registered in `src/atoms/index.ts` with its `name`, `description`, and the `atom` instance.
    *   Consolidation of separate state and mutation atoms into a single atom, if applicable.
    *   Correct import paths and dependency management.
    *   Adherence to established naming conventions.
4.  **Implement Changes:** Apply the necessary refactoring using tools like `replace_in_file` or `write_to_file` to modify the atom's source code and related files.
5.  **Test & Verify:** Create or update unit tests for the `{atomName}Fn` to ensure its correctness. Update `src/atoms/index.ts` with any changes to type definitions and ensure the atom's registration is accurate.
6.  **Lint & Build:** Execute the linting and build check scripts: `./check-lint-build-errors.sh src/atoms/{atomName}.ts` and `./check-lint-build-errors.sh src/atoms/index.ts` to ensure code quality and catch any build issues.

Special attention should be given to instances of `atomFamily`, as they may require specific adaptations to the standard refactoring pattern.

This task provides the general framework. It will be expanded into subtasks for each atom or group of related atoms.

# Test Strategy:
The refactoring of each atom will be tested as follows:
1.  **Unit Testing:** Create or update comprehensive unit tests for the core logic function (`{atomName}Fn`) in its respective `{atomName}.test.ts` file.
2.  **Linting and Building:** Run `./check-lint-build-errors.sh src/atoms/{atomName}.ts` and `./check-lint-build-errors.sh src/atoms/index.ts` to ensure code quality, style compliance, and successful build.
3.  **Code Review:** A thorough code review by another developer against the standards outlined in `README.md`, particularly the 'Things to check when refactoring atoms to use the new pattern' checklist.
4.  **Integration Check:** Verify that the atom is correctly registered in `src/atoms/index.ts` and that its type definitions are accurate and exported.
5.  **Visual/Functional Check (if applicable):** For atoms with UI implications or complex interactions, a manual visual check or basic rendering test in a test environment or Storybook (if Storybook is in use and updated for the atom) should be performed.
